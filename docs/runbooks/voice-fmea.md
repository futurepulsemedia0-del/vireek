# Voice path FMEA

Scope: carrier → webhook → voice engine → ASR/LLM/TTS → tools → CRM/calendar → notifications.
Basis: the repo snapshot `vireek-main_5.zip` (older than the live repo; re-verify rows marked **[verify]** against the live code). "Mitigation (now)" is what exists after the voice-resilience change set, "Before" is the snapshot.

Legend: **S** severity 1-5 (5 = a call is lost or an emergency is missed), **L** likelihood 1-5, **D** detectability 1-5 (5 = hard to detect). RPN = S×L×D. Ratings are engineering judgement, not measured rates.

Path today: PSTN → Vapi-hosted or Twilio-imported number → Vapi → `vapi-webhook` (`assistant-request` picks the assistant, tools via `tool-calls`, `end-of-call-report` persists). Separate Twilio path: `pbx-voice` (business phone system, voicemail, IVR). Vapi is referenced in 162 files and Twilio in 82 (grep of the snapshot).

## Highest residual risks
1. **Numbers pointed straight at the engine have no independent catch-all** (rows 3, 5). Fix: Twilio-owned numbers → `voice-front-door`.
2. **No secondary AI engine** (row 5). Degradation replaces the AI with voicemail/forward; it does not equal the AI experience.
3. **Everything shares one Supabase project** (rows 12, 21): ladder state, status page and reconcile live with the data they protect.
4. Vapi-side fallbacks (`fallbackDestination`, transcriber/voice/LLM fallback plans) are configuration we cannot verify from the repo.
