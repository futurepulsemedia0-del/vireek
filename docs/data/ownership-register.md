| `unclassified` | No rule matched. Allowed only as an INFERRED baseline row; never in a reviewed entry |

### Ownership category [COUNSEL]

| Category | Working meaning (engineering) |
|---|---|
| `customer` | Supplied by, or generated about, one tenant’s own business. The tenant is the data owner / controller. |
| `derived` | Computed by Vireek from customer data (scores, aggregates, models, AI output). Who owns it is open. |
| `vireek` | Vireek’s own records, or platform content that contains no customer data. |

### Steward role

A **role**, not a person: `platform`, `backend`, `data`, `security`, `compliance`, `voice`, `frontend`, `mobile`, `billing`, `integrations`, `support` (the `.github/CODEOWNERS` tokens plus the `docs/OWNERS.md` areas). Named owners are still TBD in `docs/OWNERS.md`; until they are assigned, a steward role means "the team that must answer for this table".

### Retention link

<a id="r-configurable"></a>**`configurable`** — A tenant retention policy can sweep this table (`data_retention_policies`, `data-retention-sweep`). Period is tenant-set; no default period exists.  
<a id="r-erasure-only"></a>**`erasure-only`** — Removed by `delete-account` (listed in `OWNED_TABLES`). No retention period is defined.  
<a id="r-documented"></a>**`documented`** — An explicit entry points to the document that governs retention.  
<a id="r-none"></a>**`none`** — No retention rule found in the repository. This is a gap; see the policy draft.  

### Scope key

The first tenant column found (`user_id`, `account_owner_id`, `owner_id`); `—` means the table has none (platform-wide or keyed another way). Account-owner scoping follows the existing `accountOwnerId` / RLS pattern; this column does not replace the RLS audit.

## 4. Adding a table

1. Add the migration that creates the table.
2. Add an entry to `docs/data/ownership-register.data.json` under `entries`: `{ "dataClass": "...", "steward": "...", "ownership": "customer|derived|vireek" }`, optionally `retentionRef` (repo path, optional `#anchor`) and `counsel` (the open legal question).
3. Run `npm run data:register` and commit the regenerated register.

CI (`npm run data:register:check`) fails when a table has no entry, when the register is stale, when an entry names a table that no longer exists, or when a vocabulary value is invalid. Inferred rows are frozen for legacy tables in `docs/data/ownership-register.baseline.json`; promoting a table to a reviewed entry removes it from the baseline automatically.
