# Vendor exit plans

> **DRAFT — not approved.** Owner: _to be assigned_. Nothing here states that an exit has been rehearsed, that a vendor contract allows it, or that any compliance requirement is met. Tags: **[VERIFY]** unconfirmed vendor fact · **[COUNSEL]** legal or contractual question.

One page per external provider found in `supabase/functions`. Each page answers: what depends on it, how to get data out, alternatives, estimated switch effort, last drill date. Related: `docs/compliance/policies/vendor-management.md`, `docs/compliance/transfers-and-contracts.md`, `docs/compliance/data-map.md`, `docs/integrations/providers/OWNER_REGISTER.md` (account owners, rotation dates), control VND-01 in `docs/compliance/soc2/controls.json`.

## How the pages are built

- The **measured block** in each page (functions, shared modules, secret names, hosts, identifier columns) is generated: `node scripts/compliance/gen-vendor-exit.mjs`. The rest is hand-written and must keep its tags.
- `node scripts/compliance/gen-vendor-exit.mjs --check` fails when a provider appears in code without a page, a block is stale, an outbound host is unclassified, or a page lacks a required heading/field. Never-drilled and overdue drills are warnings; add `--strict-drills` to fail on them.
- **Blast radius is import reachability**, an upper bound. A failover chain (AI providers) makes every importing function "reach" every chain member.
- Some pages group vendors that share one adapter engine and one exit path (`crm-connectors`, `pm-suites`, `property-data-providers`, `customer-data-destinations`, `public-data-apis`, `package-cdns`, `apple`, `google`, `meta`, `microsoft`).
- **Out of scope of this scan:** providers used only from `src/` (browser), `worker/`, `.github/`, mobile apps, or managed outside code (registrar, e-mail for staff, GitHub, Sentry). Add them when the scan scope is widened.

## Tiers and effort (proposed; management decides)

| Tier | Meaning | Drill cadence |
|---|---|---|
| 1 | Outage or exit stops the core product, or irreplaceable data lives there | every quarter |
| 2 | A major feature or channel degrades, or lock-in is costly | twice a year |
| 3 | Optional, tenant-chosen, failover-only, or public data | once a year |

Effort scale: S < 2 person-weeks · M 2–5 · L 5–10 · XL > 10 (one engineer, tests and rollout included; vendor lead times and tenant coordination excluded). All estimates carry **[VERIFY]**: nobody has timed a switch.

## Adding a provider

1. Add an entry to `PROVIDERS` (or `IGNORED_HOST` for non-dependencies) in `scripts/compliance/gen-vendor-exit.mjs`.
2. `node scripts/compliance/gen-vendor-exit.mjs --init <slug>`, fill every **[FILL]**.
3. Review the public sub-processor list and customer notice if personal data is processed [COUNSEL].
4. `node scripts/compliance/gen-vendor-exit.mjs` then `--check`.

Drills: [QUARTERLY_DRILL_CHECKLIST.md](QUARTERLY_DRILL_CHECKLIST.md).
