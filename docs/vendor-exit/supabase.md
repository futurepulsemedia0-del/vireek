## 1. What depends on it

Postgres with tenant isolation by row-level security (see `docs/security/rls-audit.md`), Auth, Storage and the Edge Functions runtime. Almost every function creates a Supabase client, so there is no single seam: the seam is the Postgres wire protocol plus the supabase-js API surface.

## 2. Data export method

Logical backups: edge function `dr-backup-run` (control AVL-02) and `pg_dump` against the project connection string. Restore rehearsal: `dr-restore-drill` (AVL-03). Storage objects via the S3-compatible endpoint or CLI [VERIFY]. Auth users (including password hashes) are readable from the `auth` schema with the service role [VERIFY]. Edge function source is in this repo; secret VALUES are never exported — re-enter them from the secrets manager. `docs/DB_BACKUP_RESTORE.md` records that its drill result table is still empty.

## 3. Alternatives

Self-hosted Supabase (open-source stack); plain PostgreSQL on a managed service (AWS RDS/Aurora, Google Cloud SQL, Neon, Crunchy Bridge) with a separate auth layer (Keycloak, Auth0, Cognito) and S3-compatible storage; functions on Deno Deploy or a container platform. None evaluated; no pricing or terms verified.

## 5. Exit steps

1. Declare the trigger (vendor insolvency, price/terms change, security incident, regulatory block, quality drop) and record the decision and date.
2. Freeze new dependency: feature-flag new onboarding to the vendor.
3. Run the export in section 2 and verify row counts and checksums against Vireek tables; store the export in a private bucket.
4. Build or enable the replacement behind the seam in section 1; shadow-run before any traffic moves.
5. Cut over progressively; keep rollback available until the vendor contract ends.
6. Revoke vendor credentials, request deletion of vendor-held data and written confirmation [COUNSEL], and update the public sub-processor list and customer notice (`scripts/compliance/gen-subprocessors-by-region.mjs --check`) [COUNSEL].
7. Provider-specific: RLS policies call Supabase auth helpers (`auth.uid()` / JWT claims); a non-Supabase Postgres needs an equivalent session-claims layer before any policy works [VERIFY].
8. Provider-specific: Rehearse first with a restore of the latest logical backup into a plain PostgreSQL instance and run `supabase/tests/database` pgTAP files against it.
9. Provider-specific: Check `docs/generated/CRON_JOBS.md` for scheduled jobs that must be re-created on the target.
